# 端侧向量模型：bge-small-zh → Core ML

聊天检索里「向量」那一路的模型是怎么来的。半年后想换模型或者重新转换，照这份走。

## 为什么是这个模型

先试的是 Apple 原生的 `NLEmbedding.sentenceEmbedding(for: .simplifiedChinese)`。
它确实可用（640 维），但在日记语料上 **recall@5 只有 0.11，比随机的 0.17 还差**，
而且有明显的 hub 现象：「答辩过了，走出来那一刻腿都是软的」这一条在四个查询里有三个
都排进前三，它跟什么都近。原因大概是它拿书面语料训的，对付碎碎念本来就吃亏。
**别再试它。**

`BAAI/bge-small-zh-v1.5` 是专门训中文语义相似度的，实测 recall@5 0.80 / MRR 1.00。

| | 层数 | 隐层 | 参数 | 词表 | 转换后体积 |
|---|---|---|---|---|---|
| bge-small-zh-v1.5 | 4 | 512 | 24M | 21128 | 45 MB |

## 环境（版本是踩出来的，别随意升）

```bash
python3 -m venv venv
./venv/bin/pip install "torch==2.7.*" "transformers<5" coremltools
```

- `transformers` 必须 5 以下。5.x 的 `BertModel.forward` 里有 `new_ones` 这类算子，
  coremltools 转不了。
- `torch` 2.14 会在 `aten::Int` 上报 "only 0-dimensional arrays can be converted"。
  2.7 是 coremltools 9 测过的版本。

## 转换

关键在**绕过 `BertModel.forward`**，直接调 `embeddings` 和 `encoder`，
把 position_ids 和 extended attention mask 显式传进去。走官方 forward 转不过去。

另外两件事都要做在模型里，Swift 侧就只剩点积了：取 CLS、L2 归一化。

```python
import torch, torch.nn.functional as F, numpy as np, coremltools as ct
from transformers import AutoTokenizer, AutoModel

MODEL, SEQ = "BAAI/bge-small-zh-v1.5", 128
tok = AutoTokenizer.from_pretrained(MODEL)
base = AutoModel.from_pretrained(MODEL, attn_implementation="eager").eval()

class Embedder(torch.nn.Module):
    def __init__(self, m, seq):
        super().__init__()
        self.emb, self.enc = m.embeddings, m.encoder
        self.register_buffer("pos", torch.arange(seq).unsqueeze(0))
    def forward(self, input_ids, attention_mask, token_type_ids):
        h = self.emb(input_ids=input_ids, token_type_ids=token_type_ids, position_ids=self.pos)
        ext = (1.0 - attention_mask[:, None, None, :].float()) * -1e4
        h = self.enc(h, attention_mask=ext)[0]
        return F.normalize(h[:, 0], p=2, dim=1)

w = Embedder(base, SEQ).eval()
ex = tok(["测试一句话"], padding="max_length", truncation=True,
         max_length=SEQ, return_tensors="pt")
args = tuple(ex[k].int() for k in ("input_ids", "attention_mask", "token_type_ids"))

with torch.no_grad():
    traced = torch.jit.trace(w, args, strict=False)

ml = ct.convert(
    traced, convert_to="mlprogram",
    inputs=[ct.TensorType(name=n, shape=(1, SEQ), dtype=np.int32)
            for n in ("input_ids", "attention_mask", "token_type_ids")],
    # dtype 必须显式写 float32。不写的话跟着 compute_precision 变成 fp16，
    # Swift 那边按 fp32 读 512 个数就会越界 SIGABRT。
    outputs=[ct.TensorType(name="embedding", dtype=np.float32)],
    compute_precision=ct.precision.FLOAT16,
    minimum_deployment_target=ct.target.iOS17)
ml.save("BGESmallZh.mlpackage")
```

转完必须验一下 PyTorch 和 Core ML 的输出还是不是同一个东西。逐条余弦应该在 0.999 以上，
最大绝对误差 0.003 量级（fp16 计算的正常损失）。**低于这个数说明转换过程丢了东西。**

## 装进项目

```bash
cp -R BGESmallZh.mlpackage Slime/Recall/
```

词表也要导出来，Swift 的分词器读它：

```python
with open("Slime/Recall/bge-vocab.txt", "w") as f:
    for t, i in sorted(tok.get_vocab().items(), key=lambda kv: kv[1]):
        f.write(t + "\n")
```

工程是文件系统同步的，放进目录就自动进 target，`.mlpackage` 会在编译时变成
`.mlmodelc`。**运行时加载的是后者**，所以 Swift 里写的是
`Bundle.main.url(forResource: "BGESmallZh", withExtension: "mlmodelc")`。

## 换模型之后必须重导黄金对照

`SlimeTests/BertTokenizerTests.swift` 里钉着一批「原文 → token id」的对照，
它们是 Swift 分词器唯一的判据。分词错了不会报错，只会静静地编出错的 id。

```python
for s in ["今天又被组长说了", "ABC大写", "组长said：ok", ""]:
    print(s, tok(s, add_special_tokens=True)["input_ids"])
```

顺带记一个反直觉的配置：这个模型 `do_lower_case = False`，
所以大写英文查不到词表，`"ABC"` 整个变 `[UNK]`。看着像 bug，是模型本来的行为，
Swift 侧**不要**自作主张小写化，否则就对不上了。

## 还没做的

权重量化。coremltools 支持把权重压到 8 位甚至 4 位，45 MB 大概能降到十几 MB。
代价是精度损失，压完要重跑 eval 看 recall 掉多少。
