> **这是一份骨架，不是成稿。** 每节列了:主旨 / 要讲什么 / 素材在哪 / 预期追问。
> 正文得你自己写 —— 面试时讲出来的必须是你的话，照着别人的行文背会露馅。
>
> **写之前先定调子。** 这份文档不该是「项目介绍」——功能列表谁都会写，不稀缺。
> 它该是**「我在这几个地方做了判断，这是证据」**。
> 所以每一节都按同一个形状讲:
>
> **问题 → 我最初怎么想 → 现实/数据怎么反驳 → 最终怎么定。**
>
> 中间那一步不能省。**一个只有结论的文档，和一个抄来的文档，看起来是一样的。**

## 1. 主动关怀:怎么让一个 AI 功能不变成打扰 ★★★

**主旨**:这一节要让人看到你**先想清楚了职责边界，才开始写代码**。

### 1.1 v1 错在哪

- v1 是三条本地规则:「连续三篇 sad = 低谷」
- 为什么废掉:**用数数的方式下情绪断言** —— 拿算术猜语义
- 而且**趋势是「天与天」之间的事，不是「篇与篇」之间的事**

> 这一段是全文的定调。后面所有设计都在防同一个错误。

### 1.2 分层

- 本地闸门(算术) → AI(语义) → 本地(记账)
- 闸门只回答三件算术:有新蛋吗 / 窗口内够 3 天吗 / 距上条退场满冷却了吗

### 1.3 权限不对称

- **AI 有一票否决权，没有一票通过权**
- 闸门不放行，AI 根本没机会开口

### 1.4 一条自我约束

- **闸门代码里不允许出现任何 `emotion` 字样**
- 而且它拿不到任何仓库 —— **想违规也违规不了**
- 讲清楚:这不是洁癖，是防止哪天有人「顺手」在闸门里加一句情绪判断，就退回 v1 了

素材:[`Slime/Care/CareGate.swift`](../Slime/Care/CareGate.swift)、CLAUDE.md §2.1

**预期追问**
- 「为什么不干脆全交给 AI?」→ 成本(每次打开都调)、不可预测、断网就没有兜底
- 「闸门那三条数字怎么定的?」→ 诚实回答:3 天是「够看出走向」的经验值;1 天冷却是从 3 天降下来的，因为「要不要换」交给 AI 之后本地只剩兜底
- 「为什么不让闸门看情绪?」→ 1.1

## 2. 怎么知道它做得好不好 ★★

**主旨**:LLM 的输出没有「对不对」，只有分布 —— 所以要有尺子。

要讲:
- **41 条 golden set**，每条标「该说 / 不该说」+ 为什么这么标
- `expected` 那一列**是产品判断，不是代码** —— 它决定母鸡的性格:话多还是话少、宁可漏说还是宁可多说
- **5 次采样**(temperature 0.8，跑一次测的是运气不是模型)
- 当前基线:**precision 0.83 / recall 0.95**
- **四条稳定失败**，三跑全是同样四条 —— 不是噪声
- **文案抽查**:算术的硬判(禁词，出现即失败)、语义的只报不判(范围词要看上下文)

**别只报分数，要报归因**:
> 四条失败全是 FP(不该说却说了)，FN 是 0。
> 「该说」那 19 条全对、17 条 5/5。
> **模型的「该开口」判断满分且稳;所有问题都在「该闭嘴」那一侧。**

素材:[`SlimeTests/CareEvalCases.swift`](../SlimeTests/CareEvalCases.swift)、CLAUDE.md「eval 09-23 全量基线的诊断」

**预期追问**
- 「0.83 不高啊?」→ **这正是要主动说的**:满分先怀疑题太简单。而且我知道是哪四条、为什么、下一步怎么办(见第 3 节和第 5 节)
- 「标注是你自己定的，会不会循环论证?」→ 承认是主观的，但每条都写了理由和分界线，而且**改过标注**(#37 测完从 false 翻成 true)——标注跟着证据走

## 3. 三次「我推错了，测试推翻了我」 ★★★

**主旨**:这一节展示的不是结论，是**你不靠直觉下结论**。三个故事各两三句，最后一段方法论。

### 3.1 「退场后最容易重复」—— 一测不成立

- 推理链很顺:关怀退场后 `isNew` 字段消失，模型要自己比日期 → 容易把旧话换个说法重说
- 建了用例去测 → **20 次里零次重复**
- 而且做了对照:挂着状态的同类场景**也一样失败** → 那个问题和退场无关
- **真正的问题是另一个**:模型有一半概率以为已退场的关怀还挂着

### 3.2 改完 prompt 分数掉了 —— 是噪声

- 改一行文案措辞 → recall 从 1.00 掉到 0.95，多了一条 FN
- 解释还很顺:「文案约束收紧 → 模型不敢开口」
- 差点据此回退。先把那条用例单独 A/B 各 10 次 → **5/10 vs 6/10，差别在噪声里**
- **n=5 的全量跑之间，一两个点的分差没有意义**

### 3.3 「精简 prompt 能救那四条」—— 只救了一条

- 假设:prompt 97 行超过了实测的失效阈值(89 行失效 / 68 行生效)，规则被稀释
- 精简到 71 行(**只合并重复、不增删规则**) → #10 从 8/10 降到 4/10，真的救活了
- 但「保持」那族三条**纹丝不动**，9~10/10 判说
- 结论反过来更有价值:**那三条不是稀释问题，是模型的立场问题** ——
  它有个压不住的先验:「这个人还在难受，说一句总比沉默好」

### 小结:三条方法论

1. **结构推理要先测再信。** 推理顺 ≠ 结论对
2. **单条用例的因果，必须单独做 n=10 的 A/B。** 两次全量跑的分差看不出小改动
3. **稳定判反 ≠ 摇摆。** 5/5 判反说明模型有个清楚的读法 —— 先认真看它的理由，再决定谁错

素材:CLAUDE.md「基线的噪声」「prompt 精简实测」两节

**预期追问**
- 「那四条你最后修了吗?」→ 修了一条(#10)，另外三条证明了修不了，**并且写下了为什么别再试** ——
  这比修好它更有用，因为它阻止了以后反复踩

## 4. 一个 bug 的完整过程:「说」和「在」 ★★

**主旨**:防止全文全是抽象判断，需要一个看得见摸得着的手艺故事。

要讲:
- **现象**:从广场 tab 切回首页，母鸡就把同一句话重新说一遍。一天来回切五次 = 五次隆重登场
- **病根**:一条关怀有两个生命周期，被混成了一个
  - 内容的生命(最多 3 天，AI 判替换)
  - 露面的生命(滑出 → 淡出)
  - **动画属于「说」，不属于「在」**
- **修法**:`firstSeenAt` 落库，分 `.speaking` / `.lingering` 两种形态
- **一个容易写错的细节**:不能在动画播放那一刻记 —— 那记的是「播过动画」。
  用户一开 App 就点鸟巢，卡片刚冒头就被收掉，那次要是算数，**这条关怀就白说了**。
  所以是「滑出后活满 3 秒才算」，被打断就取消
- **三个连带修复**:卡片不再自己消失之后，「作废的话一直挂着」「新关怀进不来」
  「在看不见的页面上被标记成看过」这三个问题才浮出来

素材:CLAUDE.md「卡片两种形态」、[`Slime/Views/CareCardView.swift`](../Slime/Views/CareCardView.swift)

**预期追问**
- 「怎么发现的?」→ 老实说:改别的东西时在模拟器上手点，切了两次 tab 发现它又滑出来了
- 「为什么是 3 秒?」→ 要短于兜底、长于一次误触。没有精确依据，是可调的常数

## 5. 一个**没有做**的决定:频率是要保护的信号 ★★★

**主旨**:这一节最难写，也最值钱 —— 它展示的是克制。

要讲:
- **先问对问题**:「母鸡该多久说一次话」问错了。真正的问题是**「她开口这件事还有没有信息量」**
  - 每次打开都说 → 用户正确地推断出「这是个函数，不是观察」
  - 偶尔说 → 「她今天说话了」是个**事件**
  - **频率不是要调的参数，是要保护的信号**
- **否掉了一个直觉方案**:纯频率限制(N 天最多换一次)。
  AI 总想换 + 本地总卡 N 天 = 精确的「每 N 天一换」，**一个完美的定时器**，比没有兜底更容易被识破。
  → **用算术压语义，压出来的是规律，而规律本身暴露机制**
- **候选方案**:把「换内容」和「重新开口」拆开 ——
  有新证据才滑出来，只是换个说法就静默更新。判据用现成的 `isNewEvidence`，纯算术
- **为什么没做**:前提是「AI 确实经常想换」，而那只在人工构造的边界用例上测过。
  **为一个没观测过的现象改设计，是在猜。**
  → 所以先做了可观测(第 9 步的 debug 页)，去拿真实分布

素材:CLAUDE.md「候选方案:把『换内容』和『重新开口』拆开」

**预期追问**
- 「那你什么时候会做?」→ debug 页上「替换里引用全是旧日子」占比过半就做，很小就不做
- 「不怕做不完显得没完成?」→ 这正是要正面接的:**十步走完了九步，第十件事我故意停下来等数据**

## 6. 检索(RAG):让母鸡能「拿起来说」 ★★

**主旨**:第二个系统，证明不是只会做一个东西。

要讲:
- 管线:提炼检索词 → 三路召回(关键词/向量/情绪同调) → RRF 融合 → LLM 重排 → 生成(可以选择不说)
- 端侧向量:`bge-small-zh-v1.5` 转 Core ML，45MB，手写 BertTokenizer
- eval:融合 recall@10 = 1.00；单路关键词 0.95、单路向量 0.90
- **最值得讲的一条**:**时间近因绝不能进排名**
  - 相关回忆的价值恰恰在于久远
  - 近因一参与打分，三个月前那件真正相关的事就永远上不来
  - 整套检索会退化成「最近 N 天」——那还不如直接把最近几天塞进 prompt
  - **这条线一松，整个 RAG 就白做了**
- 一个否定结果:Apple `NLEmbedding` 中文句向量 recall@5 只有 0.11，**比随机的 0.17 还差**，有 hub 现象

素材:CLAUDE.md「母鸡聊天的检索(RAG)」、[`docs/端侧向量模型.md`](端侧向量模型.md)

**预期追问**
- 「为什么端侧不用 API?」→ 隐私(日记全文)、成本、离线可用
- 「recall 1.00 是不是题太简单?」→ **主动承认**:4 条用例里 3 条怎么测都是 1.00，eval 已经饱和，
  想继续调参得先把 golden set 做难做大

## 7. 技术栈与工程约定 ★

**主旨**:交代一下，**别展开**。这节是背景不是卖点。

- 全 UIKit，纯代码搭 UI，无 Storyboard
- 列表统一用 Compositional Layout + Diffable Data Source
- Core Data;**模型改动必须加新版本**，旧版本留在仓库里当迁移源(踩过:就地改版本会让装过旧版的设备启动即崩)
- MVVM + Repository;跨仓库 + 网络的流程放 `Services/`
- `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` —— 一切默认主线程隔离，纯值类型要显式 `nonisolated`

## 写的时候注意

1. **每节都要有一个可验证的东西** —— 一个数字、一个代码位置、一次实测。
   没有的那节，说明你还没真想清楚
2. **主动认领弱点**。0.83、recall 1.00 的检索 eval、key 在客户端 —— 这些藏不住，
   **你先说出来，它们就从减分项变成了「他知道自己在哪」**
3. **别写成流水账。** 不要「我先做了 A 再做了 B」，要「这里有个判断，证据是这个」
4. **长度**:每节 300~600 字。全文控制在读者十分钟能看完 —— 超了就没人看完
